# EventConductor for VS Code

Edit EventConductor workflow definitions (`.ec` files) as an **interactive graph** or as
plain **YAML/JSON** with schema validation — both views edit the same file.

## Features

- **Graph editor** (default): opens any `.ec` file — or `*.workflow.yaml` / `*.ec.yaml` (and
  `.yml`), for those who keep the `.yaml` extension — as the EventConductor workflow graph.
  Drag nodes, **Shift+drag** to draw precondition lines, click to filter, zoom/pan/fit,
  minimap, and the animated token simulation — the same component used inside the app.
- **Delete** (or **Backspace**) removes the selected node or connection. Deleting a node
  also clears every reference to it — preconditions and compensation pointers — so the
  file it writes back is still a definition the engine will load.
- **Dual mode**: the graph is backed by the text document, so graphical edits update the
  file and text edits update the graph. Use **EventConductor: Open as Text** (editor title
  or command palette) to edit the YAML/JSON directly, and **Open as Graph** to go back.
- **`.ec` is JSON *or* YAML**: the format is detected from the file's content and preserved
  on graphical edits.
- **Schema validation**: workflow files (`.ec`, `*.workflow.yaml`, `*.ec.yaml`) are validated
  against the workflow-definition JSON schema, and `.ecform` / `.ecrule` / `.ectask` against
  theirs, through *YAML* by Red Hat (installed with this extension): the schemas are contributed
  with `yamlValidation`, so no `yaml.schemas` setting is needed.

## Agent catalogue

`AGENT` nodes can be drawn offline. To select a published agent and inspect its configured MCP,
RAG and peer capabilities, run **EventConductor: Configure Agent Catalogue** from the command
palette. Enter the workflow engine's full `/api/workflow-agents` URL and choose HTTP Basic,
Bearer token or no authentication. For the isolated local acceptance environment, use
`http://127.0.0.1:18105/api/workflow-agents`, HTTP Basic, and the local operator credentials
generated by that environment. The engine must be running and reachable from the VS Code
extension host (including when using Remote SSH or a dev container).

The endpoint is saved in the user setting `eventconductor.agentCatalogueUrl`. Credentials are
stored in VS Code SecretStorage, bound to that endpoint; they are never saved in `.ec` files,
workspace settings, or sent to the graph webview. Re-run the command to change credentials.
Authentication requires HTTPS except on localhost. Requests time out after ten seconds and
do not follow redirects. Catalogue access is disabled in untrusted workspaces.

The published agent owns MCP, RAG and peer configuration. These fields are read-only in the
graph and refresh from the selected catalogue entry; they are not copied into the workflow.
Besides selecting the published agent, its editable call configuration is **Task prompt**,
**Input** and **Output variable**. Changing agents removes previous capability overrides.
For older workflows containing explicit capability lists, the editor displays those restrictions
and offers **Use catalogue configuration** to remove them deliberately. Opening a workflow
does not change its execution semantics.

The extension host loads the catalogue and passes only agent IDs, names and capability lists
to the graph. The web application retains its same-origin restriction. Loading the list does
not execute an agent; the engine still validates references and capability selections when
importing the workflow.

## Develop

```bash
cd plugins/vscode-eventconductor
npm install
npm run compile     # syncs the graph bundle + schema, then compiles TypeScript
npm test            # compiles and tests catalogue transport and the editor bridge
```

Then press **F5** in VS Code (Extension Development Host) and open a `.ec` file.

`npm run compile` runs `scripts/sync-assets.js`, which copies the graph bundle
(`workflow-graph.js`) and the JSON schema from the main repo into the extension, so the
extension always ships the current component. Re-run it after rebuilding the frontend.

> Note: graphical edits round-trip the definition through the model, so YAML comments and
> exact formatting are not preserved when you edit in the graph — use the text editor when
> you need to keep them.
